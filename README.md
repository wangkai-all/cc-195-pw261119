# 地理点加工仓（Geo Grid Warehouse）

把带经纬度的事件**确定性地**分配到固定等经纬网，按**多级格网 + UTC 时间分区**入仓，
并提供三种计数口径的**守恒核对**。纯本地项目：零第三方运行时依赖、无地图服务、
前端用原生 SVG 绘制格网热力图。

## 快速开始

```bash
npm start          # 启动 http://localhost:3000（自动持久化到 data/warehouse.json）
npm test           # 14 项规则/仓库单元测试
npm run demo       # 端到端守恒演示（45 项断言，退出码 0 即全过）
```

浏览器打开 `http://localhost:3000`，在「① 导入与版本」页点三个**一键演示**按钮即可复现全部场景。

## 格网规则（确定性，版本化）

布局参数：`factor`（细分因子，2=四叉 / 3=九分…）与 `maxLevel`。
层级 `level k` 的全球划分为 `2·factor^(k+1)` 列 × `factor^(k+1)` 行，
每层都完整覆盖全球，无残块；步长 `360/lonCount`、`180/latCount`。

| 规则 | 规定 |
|---|---|
| 半开区间 | 每个单元覆盖 `[low, high)`，本初子午线、任意格线、赤道上的点只归入编号更大（右/上）的单元，**边界点不可能落入两个单元** |
| 日期变更线 | 经度 `+180` 归一为 `-180`，与 `-180` 同属最左列（列号 0），不产生右越界单元 |
| 极点 | `lat = +90` 归入最上行、`lat = -90` 归入最下行，不产生极外单元 |
| 越界/缺失 | 除上述端点外，`lon ∉ [-180,180]` 或 `lat ∉ [-90,90]`、缺失、非有限数一律**不夹紧**，进隔离区 |
| 浮点容差 | 距格线 ≤ 步长 × 1e-9（亚毫米级）的表示误差吸附到格线，只修二进制误差、不改规则语义 |
| 时间分区 | 按 UTC 自然日 `YYYY-MM-DD`；时间缺失/非法归入固定分区 `__UNKNOWN__`，不影响坐标入格 |
| 层级父子 | 父单元 `(level-1, ⌊col/factor⌋, ⌊row/factor⌋)`，每个父单元恰好含 `factor²` 个子单元 |

单元 ID 全限定为 `版本/层级:列,行`，例如 `v1/L2:c8,r4`；跨版本 ID 不重叠。

## 入仓与修订语义

- **多级物化**：一个事件在 `0..maxLevel` 每一层各落一个单元，各层事实表独立计数，
  并按时间分区维护 `byPartition` 明细与 `eventIds`。
- **原始坐标保留**：事件台账保存首报原始载荷；任何修订只追加 `revisions` 记录，不覆盖历史。
- **重复事件**：同 `event_id` 且坐标/时间完全一致 → 幂等忽略（不翻倍、不写修订）；
  坐标/时间不同 → 走修订。
- **增量修订（先撤回、后计入）**：先从**全部版本、全部层级、旧时间分区**撤回旧坐标贡献，
  再按新坐标重新计入。撤回与计入分别写审计日志（`event.withdraw` / `event.revise`），
  任何中间态都不会让一个事件被两个单元同时计数。
- **隔离与恢复**：非法坐标进隔离区（`quarantined`）；后续修订为合法值时自动恢复入仓，
  隔离条目标记 `recovered` 但保留可审计；合法坐标被错改成越界值则撤回入格并转回隔离。

## 三种计数口径与守恒核对

| 口径 | 数据来源 |
|---|---|
| 物化表 | 入仓时直接写入各层的计数事实 |
| 底层汇总 | 只从最细层（`maxLevel`）沿父子关系向上 rollup，不读任何上层数据 |
| 直接计算 | 只用原始坐标按目标层规则重新落格，完全不读事实表 |

每组核对含 4 项检查：

1. 物化总数 = 在册有效事件数（可按分区过滤）
2. 底层汇总 = 直接计算（逐单元 diff）
3. 物化表 = 底层汇总（逐单元 diff）
4. 有效事件 + 开放隔离 = 事件总数（全局守恒）

## 数据版本（规则改版）

规则改版 = **新建布局版本**（如 `v1` factor=2 → `v2` factor=3），服务端拒绝覆盖同 ID 旧布局。
新版本创建时对全部在册有效事件**回填**一套独立事实表；历史版本事实表冻结不变。
所有查询强制带 `versionId`，版本之间物理隔离，**查询绝不混用布局**。

## 演示场景（`src/scenario.js`，固定可复现）

- 边界点：`(0,0)`、`(90,45)`、`(-90,-45)` 验证半开区间唯一归属
- 变更线：`(±180, 0)` 同单元；极点：`(0,±90)` 入首/末行
- 越界 `(200,10)`、`(10,95)` 与缺失坐标 → 隔离区；非法时间戳 → `__UNKNOWN__`
- 完全重复上报 → 幂等不翻倍
- 增量修订：跨单元迁移（旧单元减 1/新单元加 1）、隔离恢复、合法事件错改越界转隔离
- 规则改版 v2：回填、版本隔离、两版本同总量但单元不重叠

`npm run demo` 的命令行输出逐条给出 PASS/FAIL 与账本数字。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 布局、总计数、各版本分区 |
| POST | `/api/layouts` | 新建数据版本并回填 |
| POST | `/api/import` | 导入 JSON 或 CSV（`Content-Type` 区分），含修订/幂等/隔离 |
| GET | `/api/cells?version&level&partition?` | 单元明细 |
| GET | `/api/events?version&level&col&row` | 单元下钻事件（含原始坐标） |
| GET | `/api/reconcile?version?&level?&partition?` | 守恒核对（无 level 返回该版本全部层） |
| GET | `/api/compare?version&level&partition?` | 三口径逐单元对照 |
| GET | `/api/quarantine` / `/api/audit` / `/api/events-list` | 隔离区 / 审计 / 台账 |
| POST | `/api/demo/load` · `/api/demo/revise` · `/api/demo/new-version` | 一键演示三段 |
| POST | `/api/reset` | 清空仓库 |
